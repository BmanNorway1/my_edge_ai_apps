===============================================================================
 Running an Edge Impulse image model on the Nordic Axon NPU via run_classifier()
 Project: finger_digits_v4_ei   (nRF54LM20DK, NCS edge-ai add-on v2.1.0)
 Model export: finger_digits_v3-nordic-axon-lib-v1-impulse-#1
===============================================================================

PURPOSE
-------
This document records every change needed to get an Edge Impulse "Nordic Axon
NPU library" image-classification export running through the standard Edge
Impulse run_classifier() API on an Axon-equipped nRF54L device, and WHY each
change was needed. Follow it top-to-bottom to reproduce, or use the "ADAPTING
TO ANOTHER MODEL" section at the end to port it to a different export.

The single most important (and least obvious) fix is #7: the Edge Impulse image
DSP produces INTERLEAVED (HWC) pixel data, but the compiled Axon model expects
PLANAR (CHW) data, and the SDK's wrapper does not transpose. Without that fix
the model runs happily but returns a constant, confidently-wrong class.


BACKGROUND: two ways to run the model
-------------------------------------
An Edge Impulse Axon export can be driven two ways:

  (a) RAW: call the Axon driver directly (nrf_axon_platform_init,
      nrf_axon_nn_model_infer_sync, ...). You then own ALL preprocessing:
      pixel scaling, int8 quantization, channel layout, and output decoding.

  (b) run_classifier(): the Edge Impulse API. It runs the DSP block (pixel
      unpacking + scaling), quantizes the input, runs the NPU, dequantizes the
      output and maps it to labels for you.

This project uses (b). The advantage is that scaling/quantization/label-mapping
are handled for you; the cost is a full-SDK build, C++, ~110 KB more RAM for the
DSP feature matrix, and having to patch two bugs in EI's Axon wrapper (below).


ENVIRONMENT / PREREQUISITES
---------------------------
  * NCS edge-ai add-on workspace (this used .../ncs/edge-ai-v2.1.0)
  * Board: nrf54lm20dk/nrf54lm20b/cpuapp  (512 KB SRAM, 2 MB flash)
  * The export unzipped into the app under  ei-model/  containing:
        ei-model/edge-impulse-sdk/        (the SDK, version-matched to the model)
        ei-model/model-parameters/        (model_metadata.h, model_variables.h)

 THE FIXES
===============================================================================

-------------------------------------------------------------------------------
 1. CMakeLists.txt — set DTS_ROOT / EXTRA_CONF_FILE BEFORE find_package(Zephyr)
-------------------------------------------------------------------------------
WHY: Zephyr reads these CMake variables during find_package(Zephyr). If you set
them AFTER, they are silently ignored: the conf_overlay is never applied and
custom devicetree bindings (e.g. the arducam binding) are not found.

BEFORE (broken order):
    find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})
    project(finger_digits_v3)
    list(APPEND DTS_ROOT ${CMAKE_CURRENT_SOURCE_DIR})
    set(EXTRA_CONF_FILE ./ei-model/conf_overlay.conf)

AFTER:
    list(APPEND DTS_ROOT ${CMAKE_CURRENT_SOURCE_DIR})
    set(EXTRA_CONF_FILE ${CMAKE_CURRENT_SOURCE_DIR}/ei-model/conf_overlay.conf)
    find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})
    project(finger_digits_v3)


-------------------------------------------------------------------------------
 2. CMakeLists.txt — compile the EXPORT's SDK into the app (not the module)
-------------------------------------------------------------------------------
WHY: The workspace contains a Zephyr module "edge-impulse-sdk-zephyr" that
bundles ITS OWN copy of the SDK. That copy is a DIFFERENT VERSION than the one
shipped inside your export (25+ header files differ, including core structs like
ei_model_types.h and numpy_types.h). Your model_variables.h was generated
against the EXPORT's SDK, so they must be used together or struct layouts break.

The export's edge-impulse-sdk/cmake/zephyr/CMakeLists.txt has two branches:
    if(DEFINED CONFIG_EDGE_IMPULSE_SDK)  -> builds as a separate library
                                            (ALSO triggers the module -> conflict)
    else()                               -> compiles the SDK straight into `app`

We want the else() branch. That means CONFIG_EDGE_IMPULSE_SDK must be OFF
(see fix #4), and we simply add_subdirectory the export's cmake:

    add_subdirectory(ei-model/edge-impulse-sdk/cmake/zephyr)
    zephyr_include_directories(ei-model/nordic-axon-model)
    target_include_directories(app PRIVATE ei-model)
    zephyr_compile_definitions(NRF_AXON_MODEL_NAME=${CONFIG_NRF_AXON_MODEL_NAME})

NOTE on the last line: the Axon wrapper (nordic_axon.h) token-pastes the macro
NRF_AXON_MODEL_NAME to build the model header filename and struct name, and it
#errors if the macro is undefined. conf_overlay.conf only sets the Kconfig
symbol CONFIG_NRF_AXON_MODEL_NAME; this line turns it into the compile-time
macro the wrapper actually needs.


-------------------------------------------------------------------------------
 3. CMakeLists.txt — build C++
-------------------------------------------------------------------------------
The EI SDK is C++, so the application file must be C++:

    target_sources(app PRIVATE
      src/main.cpp                 <- was src/main.c
      src/drivers/arducam_mega.c
    )


-------------------------------------------------------------------------------
 4. prj.conf — DISABLE the mismatched SDK module
-------------------------------------------------------------------------------
WHY: (see fix #2). With =y you get a duplicate-library conflict AND a
version-mismatched SDK. The export's SDK is compiled into `app` via the else()
branch, which only runs when this symbol is undefined.

    CONFIG_EDGE_IMPULSE_SDK=n          <- was =y (the original mistake)


-------------------------------------------------------------------------------
 5. prj.conf — fix model name, stack, heap, FPU
-------------------------------------------------------------------------------
    # Was a broken placeholder "finger_digits..........."
    CONFIG_NRF_AXON_MODEL_NAME="finger_digits_v3_1"

    # run_classifier()'s Axon wrapper puts a ~27 KB int8 input vector on the
    # CALLING (main) stack, plus DSP/inference call frames. 1024 is far too small.
    CONFIG_MAIN_STACK_SIZE=40960        <- was 1024

    # EI DSP is float-heavy and mallocs the ~110 KB feature matrix on the heap.
    # newlib gives malloc the remaining SRAM (this is a 512 KB part). FPU for speed.
    CONFIG_NEWLIB_LIBC=y
    CONFIG_FPU=y

    # Kept from the export:
    CONFIG_CPP=y
    CONFIG_STD_CPP11=y
    CONFIG_REQUIRES_FULL_LIBCPP=y
    CONFIG_FP16=n


-------------------------------------------------------------------------------
 6. prj.conf — size the Axon interlayer buffer to THIS model
-------------------------------------------------------------------------------
SYMPTOM (at runtime):
    interlayer buffer too small! Allocated 119808, need 175104
    ERR: nrf_axon_nn_model_validate failed!
    run_classifier failed (-36)

WHY: CONFIG_NRF_AXON_INTERLAYER_BUFFER_SIZE was a leftover value from a
different model. The required size is declared in the model header:
    ei-model/nordic-axon-model/nrf_axon_model_finger_digits_v3_1_.h
        #define NRF_AXON_MODEL_FINGER_DIGITS_V3_1_MAX_IL_BUFFER_USED 175104

FIX:
    CONFIG_NRF_AXON_INTERLAYER_BUFFER_SIZE=175104      <- was 119809

(Must be >= the model's MAX_IL_BUFFER_USED. Update whenever you swap models.)


-------------------------------------------------------------------------------
 7. nordic_axon.h — the TWO Edge Impulse SDK bugs  *** THE KEY FIXES ***
-------------------------------------------------------------------------------
File:
  ei-model/edge-impulse-sdk/classifier/inferencing_engines/nordic_axon.h
Function:
  run_nn_inference()

Edge Impulse's Axon inferencing wrapper has two defects for multi-channel
(image) models. Both must be patched. (This file is generated/downloaded, so
these patches are LOST if you re-download the export — see "MAINTENANCE".)


  7a. INPUT BUFFER TOO SMALL (buffer overflow)
  --------------------------------------------
  The wrapper sized its int8 input buffer by height*width only, dropping the
  channel count, then wrote height*width*channels into it -> stack overflow for
  RGB (27648 written into a 9216-byte buffer).

  BEFORE:
    uint32_t vector_size = ...dimensions.height * ...dimensions.width;
  AFTER (multiply by channel_cnt):
    uint32_t vector_size = ...dimensions.height * ...dimensions.width
                         * ...dimensions.channel_cnt;


  7b. CHANNEL LAYOUT: transpose HWC -> CHW  (THIS is what finally fixed it)
  ------------------------------------------------------------------------
  SYMPTOM: model runs fine but returns the SAME wrong class every frame with
  high confidence (in our case "zero" at ~98%), no matter what the camera sees.

  ROOT CAUSE: The Edge Impulse image DSP block outputs pixels INTERLEAVED
  (HWC layout: R,G,B, R,G,B, ... one triplet per pixel). The compiled Axon
  model, however, expects PLANAR data (CHW layout: the entire R plane, then the
  entire G plane, then the entire B plane). The wrapper copied the DSP output
  into the model input LINEARLY with no transpose, so the model received
  scrambled data and collapsed to a constant output.

  HOW WE PROVED IT: the export's test vectors are declared
      const int8_t finger_digits_v3_1_test_input_vector_0[3][96][96];
  i.e. [channel][height][width]  ==  PLANAR CHW. Feeding those vectors straight
  into nrf_axon_nn_model_infer_sync() (bypassing camera AND DSP) produced the
  correct expected class (see the self-test in main.cpp). That confirmed the
  model/NPU path was correct and the ONLY problem was the DSP's HWC output vs the
  model's CHW input. (There is even a leftover EI comment at this spot:
  "@FIXME!!! CHECK IF MODEL IS TRANSPOSED!" — it is.)

  FIX: transpose while quantizing. HWC source index = pixel*channels + c;
  CHW destination index = c*(height*width) + pixel.

  BEFORE:
    for (size_t i = 0; i < matrix->rows * matrix->cols; i++) {
        input_vector[i] =
            (int8_t)((matrix->buffer[i] / graph_config->input_scale)
                     + graph_config->input_zeropoint);
    }

  AFTER:
    const uint32_t in_h = ...dimensions.height;
    const uint32_t in_w = ...dimensions.width;
    const uint32_t in_c = ...dimensions.channel_cnt;
    const size_t feature_count = (size_t)matrix->rows * matrix->cols;

    if (feature_count == (size_t)in_h * in_w * in_c) {
        const uint32_t plane = in_h * in_w;
        for (uint32_t p = 0; p < plane; p++) {
            for (uint32_t c = 0; c < in_c; c++) {
                float v = matrix->buffer[p * in_c + c];        // HWC source
                input_vector[c * plane + p] =                  // CHW destination
                    (int8_t)((v / graph_config->input_scale)
                             + graph_config->input_zeropoint);
            }
        }
    } else {
        // single-channel / non-image models: plain linear copy
        for (size_t i = 0; i < feature_count; i++) {
            input_vector[i] =
                (int8_t)((matrix->buffer[i] / graph_config->input_scale)
                         + graph_config->input_zeropoint);
        }
    }

 8. src/main.cpp — the application (replaces main.c)
-------------------------------------------------------------------------------
Rewritten around run_classifier(). Key points that matter for image models:

  * Include only:  #include "edge-impulse-sdk/classifier/ei_run_classifier.h"
    That header pulls in the impulse definition, the model, and the Axon wrapper.

  * The signal callback must return ONE float per pixel, each holding an RGB888
    value PACKED as 0xRRGGBB. The DSP unpacks and scales it; you do NOT
    quantize, you do NOT lay out channels, and you do NOT maintain a label table
    (run_classifier fills result.classification[i].label / .value for you).

        static int ei_camera_get_data(size_t offset, size_t length, float *out) {
            for (size_t i = 0; i < length; i++) {
                uint16_t px = (frame_rgb565[(offset+i)*2] << 8)
                            |  frame_rgb565[(offset+i)*2 + 1];      // byte order!
                uint8_t r5=(px>>11)&0x1f, g6=(px>>5)&0x3f, b5=px&0x1f;
                uint8_t r8=(r5*255+15)/31, g8=(g6*255+31)/63, b8=(b5*255+15)/31;
                out[i] = (float)((r8<<16) | (g8<<8) | b8);
            }
            return EIDSP_OK;
        }

  * Run it:
        signal_t signal;
        signal.total_length = EI_CLASSIFIER_DSP_INPUT_FRAME_SIZE;  // one float/pixel
        signal.get_data     = &ei_camera_get_data;
        ei_impulse_result_t result = {};
        run_classifier(&signal, &result, false);
        // read result.classification[0..EI_CLASSIFIER_LABEL_COUNT-1]

  * RGB565 BYTE ORDER: we used big-endian (data[0]<<8 | data[1]) to match the
    Arducam driver. If, after the transpose fix, a few classes still look
    swapped or colors are off, flip these two bytes.

 9. Boot-time self-test (diagnostic — REMOVE once verified)
-------------------------------------------------------------------------------
main.cpp contains run_test_vectors(), which feeds the export's built-in test
vectors (already planar int8) straight into the NPU and prints PASS/FAIL vs the
expected outputs. This is the fastest way to split "model/NPU broken" from
"preprocessing broken". It embeds ~110 KB of test-vector data in flash, so
delete it (and its includes) once the pipeline is confirmed:
    - the #include <axon/...> / <drivers/axon/...> block
    - #include "nrf_axon_model_finger_digits_v3_1_test_vectors_.h"
    - the run_test_vectors() function and its call at the top of main()

===============================================================================
 ADAPTING TO ANOTHER MODEL EXPORT
===============================================================================
When you drop in a different Axon export, update these model-specific values
(everything else is generic):

  * CONFIG_NRF_AXON_MODEL_NAME  -> the new model name (matches the header/struct
                                   names: nrf_axon_model_<name>_.h / model_<name>)
  * CONFIG_NRF_AXON_INTERLAYER_BUFFER_SIZE
                                -> the new model's <NAME>_MAX_IL_BUFFER_USED,
                                   found in nordic-axon-model/nrf_axon_model_<name>_.h
  * If using the self-test, update the #include, the struct name
    (model_<name>), the labels[] array, and the *_input/expected_output_vectors
    array names.
  * The nordic_axon.h patches (7a/7b) are model-independent — reapply them to
    the new export's copy of that file.


===============================================================================
 MAINTENANCE / GOTCHAS
===============================================================================
  * The two nordic_axon.h patches (#7) live inside the Edge-Impulse-generated
    SDK. If you RE-DOWNLOAD / re-export the model, that file is overwritten and
    the patches are lost — reapply them, or these symptoms return:
        - build/stack corruption (7a missing)
        - constant, confidently-wrong class every frame (7b missing)
    Consider reporting both to Edge Impulse so a fixed export removes the need.

  * Do NOT set CONFIG_EDGE_IMPULSE_SDK=y in this workspace: it pulls in the
    version-mismatched edge-impulse-sdk-zephyr module (see #2/#4).

  * "arducam mega camera no connection" / "Video device not ready" is a HARDWARE
    issue (SPI cable seating / power), independent of any of the above. The
    self-test still runs without the camera; the live loop does not.

  * Label order comes from the model, not you. run_classifier() populates
    result.classification[i].label from model_variables.h
    (ei_classifier_inferencing_categories). Do not hand-maintain a label table
    for the run_classifier() path.
